// STAGE NOTES //
01 BINARY TO ASCII
Binary isn't a cipher — it's a number system. Every byte is 8 bits; every ASCII character is a byte. The intercepted transmission was just a URL written in 1s and 0s, broken into 8-bit groups. Groups of 01101000 01110100 01110100 01110000 01110011 = https.

Real-world relevance: Network protocols, firmware dumps, and JTAG debugging all expose data in binary or hex. Recognizing the pattern — 8-bit groups, all valid ASCII range — is what gets you there without a tool.
02 XOR WITH A HIDDEN KEY
XOR encryption is only as strong as your ability to hide the key. The key in this stage was concealed as a CSS color value: .sys-bg { background-color: #4b657900; } with the comment /* system palette -- do not modify */.

The 3-byte key was #4b6579: 0x4B = K, 0x65 = e, 0x79 = y. The key was literally "Key". Applied cyclically to each ciphertext byte, it decodes to /intermediate/stage3.html.

The lesson: In real CTFs and real vulnerabilities, secrets hide where developers assumed nobody would look. CSS comments, HTML attributes, environment variables left in source.
03 CHAINED ENCODING: ROT13 + BASE64
The double-encoded string looked like Base64 at first glance — but decode attempts would produce garbage. The clue was in the flavor text: "One was Caesar's favourite. The other is what the internet uses to move binary data around. Order matters."

The operations applied (in order): ROT13 → Base64 encode. To undo: ROT13 the encoded string first, then Base64 decode. Recognizing that ROT13 was applied before Base64 was the key insight — the resulting Base64 string after ROT13 is instantly recognizable as valid Base64, and decodes cleanly to a URL.

The lesson: When a decode produces garbage, you're either using the wrong tool or the wrong order. Enumeration is the skill.
04 HEX → BASE64 → FLAG
The final stage layered two operations on the flag itself: it was Base64 encoded, then the result was hex-encoded. Decode hex first to get a Base64 string, decode Base64 to get the flag. The subtitle // HEX → BASE64 → FLAG // told you the order explicitly — the challenge was trusting that you were reading it correctly.

The lesson: Stage 3 made you figure out the order yourself. Stage 4 told you the order and asked if you'd trust it. Both are skills.
