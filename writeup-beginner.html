// STAGE NOTES //
01 URL PARAMETER MANIPULATION
The URL is data — not just navigation. Web apps use query parameters to pass state, permissions, and identity between pages. The ?badge=noob parameter was a direct invitation to look at what the URL was doing and change it.

Real-world relevance: IDOR (Insecure Direct Object Reference) attacks work exactly this way — changing a parameter value to access resources that weren't meant to be yours.
02 ROT13
ROT13 is the universal CTF rite of passage. It's trivially breakable, which is the point — it's obfuscation, not encryption. The hint was hiding in the HTML comment in the page <head>: <!-- HINT: Did you know ROT13 is just Caesar cipher with 13 shifts? Try decoding: fgntr3.ugzy -->

The lesson: Source code comments are not hidden. They are visible to anyone who presses Ctrl+U.
03 HTML META TAGS + BASE64
HTML <meta> tags live in the <head> — invisible to the rendered page, but fully present in the DOM. Real applications use them for SEO, CSP headers, and refresh directives. The next-path attribute was waiting right there in the source: content="c3RhZ2U0Lmh0bWw=".

The lesson: Ctrl+U (view source) is the most underused tool in a beginner's kit. Base64 is recognizable by its character set and = padding — once you see it, you know it.
04 HEXADECIMAL DECODE
Every character is a number. Every number can be hex. The flag was sitting there in plain hex bytes — 46 4c 41 47 spells FLAG. Packet captures, memory dumps, and debugger output all display data this way.

The lesson: CyberChef's "From Hex" operation is one of the first recipes to have in your toolkit. More importantly: recognizing hex-encoded data in the wild is a pattern-matching skill you develop by practice.

+ STAGE 2  ·  ROT13 ROT13
What the challenge gave you:
An encoded file path: fgntr3.ugzy
1. Recognize the classic: ROT13 (Clippy hints that Julius Caesar loved this cipher). It shifts each letter 13 places forward, wrapping around the alphabet. Numbers and symbols stay unchanged.
2. Apply ROT13 to fgntr3.ugzy:
f→s, g→t, n→a, t→g, r→e, 3=3, .=., u→h, g→t, m→z, y→l
3. Result: stage3.html — navigate there to continue.

+ STAGE 3  ·  HTML SOURCE INSPECTION + BASE64 BASE64
What the challenge gave you:
A page with a fake "memory dump" button. The real clue was already in the HTML source.
1. Press Ctrl+U (or right-click → View Page Source) to view the raw HTML.
2. Near the top of the <head>, find the meta tag:
<meta name="next-path" content="c3RhZ2U0Lmh0bWw=">
3. The content value is Base64 encoded. Decode c3RhZ2U0Lmh0bWw=.
4. Result: stage4.html — navigate there to continue.
